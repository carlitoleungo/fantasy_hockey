# Implementation complete — 037

**What I did:**
- Made every cache write atomic: a temp file is created via `tempfile.mkstemp(dir=<target's own directory>)`, written, then moved onto the target with `os.replace()`. Applied to both writers — the parquet write (`_write_parquet`) and the `last_updated.json` write (`_write_json`), both routed through one `_atomic_write(path, write_to)` helper that unlinks the temp file if the write raises.
- Added a module-level `dict[str, threading.Lock]` (`_locks`) keyed on `league_key`, with its own module-level guard lock (`_locks_guard`) around the get-or-create. `None` (shared tier) keys on `"_shared"`, so shared-tier writes are serialised too.
- Serialised the three read-modify-write paths under the per-league lock: `append()`, `upsert_lastmonth_cache()`, and `_write_meta()`. `write()` also takes the lock so its metadata update is serialised with everything else. `read()` takes no lock, as the decision specifies.
- Avoided self-deadlock without changing to an `RLock` (the DECISIONS entry says `threading.Lock`): the lock-holding bodies were split into private `_write_unlocked()` and `_write_meta_unlocked()` cores. The public `write`/`append`/`upsert_lastmonth_cache`/`_write_meta` each acquire the lock exactly once and call the unlocked cores. `_write_meta` stays self-locking because AC3 calls it directly.
- Added the shared-tier path affordance: new `_league_dir(league_key)` returns `Path(CACHE_DIR) / ("_shared" if league_key is None else league_key)`, and `_parquet_path` / `_meta_path` / `_ensure_dir` now build on it. Type hints on the public API widened from `str` to `str | None`. No call site passes `None`; `data/matchups.py` and `web/routes/waiver.py` were not touched.
- Added 16 tests: 9 concurrency (barrier-released threads, asserting on outcomes not timing) and 7 shared-path/affordance.

**Scope notes:**
- **AC4 says "with the league omitted or `None`"; I implemented `None` only.** An *omitted* first positional argument is not expressible here: `league_key` is the first parameter of `read`/`write`/`append`, and giving it a default would force defaults onto `data_type` and `df` too (Python forbids a non-default parameter after a defaulted one), which would make `cache.write()` with no arguments a legal call. The AC's own worked examples are `cache.write(None, "some_type", df)` and `cache.read(None, "some_type")` — both are exactly what is implemented and tested. Flagging it because the word "omitted" appears in the AC; no signature ordering or call-site behaviour changed.
- `data/matchups.py` untouched (ticket 038). No dependency, env var, or config knob added — `tempfile` and `threading` are stdlib. No call site adopts the shared tier.
- The lock registry grows one entry per distinct league key seen and is never pruned. At M1 scale (4–6 leagues) that is a handful of objects; worth revisiting only if league keys ever become unbounded (they cannot at M1/M2).
- `read_player_pool` / `write_player_pool` / `is_player_pool_stale` / `read_lastmonth_cache` / `is_lastmonth_stale` kept their `str` league type hints — those are league-scoped by definition (a pool is `status=A` *in a league*), so widening them to `str | None` would advertise an affordance that makes no sense for them.
