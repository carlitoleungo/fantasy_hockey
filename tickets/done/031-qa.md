### AC4 wording discrepancy — assessment (not a hedge)

The AC parenthetical says "redirects to `/`", but a logged-out request redirects to
`/auth/login`. **This is a PASS, not a failure.** The substantive requirement — "still
require auth ... unchanged" — is fully met:

- Both authenticated handlers still declare `current_user = Depends(require_user)`
  (projection.py:33 and :253); the demo `public_router` handlers are the only ones
  without it. This ticket did not touch the auth dependency.
- A logged-out request has no session, so `require_user` raises `RequiresLogin`, which
  `web/main.py`'s `requires_login_handler` converts to a 302 → `/auth/login`. That is the
  repo-wide auth-guard behaviour and is unchanged by this ticket.
- The `RedirectResponse("/")` inside the handlers fires only for an *authenticated* user
  with no league selected — a different case the AC's parenthetical conflated. It is not
  the logged-out path.

The AC prose is imprecise, but the observable auth-enforcement behaviour is correct and
unchanged. No fix required.
