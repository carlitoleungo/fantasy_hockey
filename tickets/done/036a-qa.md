#### Note on AC2 evidence (what I could and could not do)

I did **not** drive the authenticated home page through a real Yahoo browser login, and I
confirmed the Engineer's stated reason as fact rather than taking it on trust:

- All three rows in `app.db` have `expires_at` in the past (`1780184957.8`, `1784857716.2`,
  `1784856758.1` against a current time of `1784991223.1`).
- `web/middleware/session.py:129-138` (`optional_user`) and `:70-79` (`require_user`) both
  call `_try_refresh` on an invalid token and, on failure, execute
  `DELETE FROM user_sessions WHERE session_id = ?` followed by `db.commit()`.

So exercising any existing row risks destroying the owner's saved sessions. I was instructed
not to modify `app.db`, and I did not.

**My assessment: the automated evidence is sufficient to settle AC2 as written, and AC2 is
not blocked on a browser walk.** Every observable element the criterion names — status code,
the four nav hrefs, their roadmap order, and the league label rendering — I verified myself
against the **real** route handler, the **real** `optional_user` dependency resolving a real
(in-memory) session row with a valid `expires_at`, and the **real** `base.html` Jinja render.
Only the Yahoo HTTP layer is mocked, patched at the importing module's namespace
(`web.routes.home.make_session`, `web.routes.home.get_user_hockey_leagues`) per
`docs/LEARNINGS.md` and DECISIONS 2026-03-03 — which is exactly the fidelity ceiling
CLAUDE.md's testing strategy permits ("Do not make live API calls in tests"). I did not
merely read the test; I re-rendered the page myself and read the resulting header markup.

Two residuals the owner may want to eyeball at their next real login, neither of which is

### Test-quality note (not a defect, no fix requested)

TC18's league-label assertion is `assert "Alpha League" in body`, which does not
discriminate: the league list in the content area also contains that string. I proved this
with a mutation probe — patching `web.routes.home.shell_context` to drop `league_name`
produced a page whose header lacks the label, yet `"Alpha League" in body` was still `True`,
so **TC18 alone would not catch that regression**.

The criterion is nonetheless properly guarded. The pre-existing
`tests/test_home_routes.py::test_home_header_shows_selected_league_name` (TC9) isolates
`body[body.index("<header"):body.index("</header>")+...]` and asserts the name appears
**there**; under the same mutation that header-scoped assertion evaluates `False`, so TC9
fails and the regression is caught. The Engineer cited TC9 as the label check in their
handoff and that citation is accurate. TC18's line is therefore redundant rather than
missing, which is a readability nit and not an AC coverage gap under DECISIONS 2026-05-31.
My `tests/test_nav_shell_qa.py::test_authenticated_home_nav_and_league_label` asserts the
ordering and the header-scoped label together so the AC2 pair is guarded in one place.
