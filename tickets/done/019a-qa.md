### Issues found

**Issue 1: Ticket AC3 states wrong HTTP status code**
- **Expected (per ticket):** `POST /api/waiver/players` with no session cookie returns 401
- **Actual:** Returns 302 to `/auth/login`
- **Why this is a spec error, not a bug:** The app has no 401 handler anywhere (`grep -rn "401" web/` returns nothing). `require_user` raises `RequiresLogin` → caught in `web/main.py:42` → `RedirectResponse("/auth/login", status_code=302)`. This is consistent with every other authenticated route. The test (TC3) correctly asserts 302, and the implementation is correct.
- **Action required:** Update the ticket's AC3 to read "returns 302 to `/auth/login`".
- **Severity:** Minor (ticket doc fix only; implementation is correct and consistent)

**Issue 2: Demo mode 500 in live server (environment-only)**
- **Expected:** `POST /demo/api/waiver/players` → 200 with `<table>`
- **Actual:** 500 — `ImportError: Unable to find a usable engine; tried using: 'pyarrow', 'fastparquet'`
- **Steps to reproduce:** `curl -X POST http://localhost:8502/demo/api/waiver/players -d "stats=Goals&position=All&period=Season&page=0"`
- **Root cause:** `data/demo.py:86 → pd.read_parquet(path)` with no parquet engine installed. Same condition as 34 pre-existing test failures.
- **Severity:** Minor (environment dependency gap — not a 019a regression). Install `pip install pyarrow` to resolve.
