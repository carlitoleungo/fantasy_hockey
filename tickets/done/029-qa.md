### Scrutiny of the two Engineer decisions
1. **Empty-state trigger keyed off empty `get_teams` (AC5):** Acceptable and correct within scope. The ticket explicitly restricts the shell to a single `get_teams` fetch ("Keep the shell's API footprint minimal"; scoreboard/matchups belong to the 030 fragment). Empty teams is therefore the only league-data signal available in the shell, and AC5's observable requirement — no league data → 200 + friendly empty-state instead of the selector — is satisfied. Caveat (owner-must-verify at 030, not a blocker here): a genuine pre-season league that has teams but no matchups will still show the selector, since the shell cannot see matchup emptiness without the fetch the ticket forbids. That "teams exist, matchups empty" case is 030's fragment responsibility. The Engineer flagged this tension explicitly; it does not fail this ticket.
2. **Fragment contract (AC2/AC3):** Verified. Emitted markup carries the parameterized `matchup_url` (not a hardcoded path — confirmed by the exactly-two occurrences both sourced from the context var), `hx-trigger` includes `load` on the container, and `<h1>` reads exactly "Week Projection". Selected team carried as query param `team_key` on the load `hx-get` and as the select's `name="team_key"` on change.
