## What I changed

One block in `.dockerignore`, the four patterns whose targets live nested inside copied
directories, now `**/`-prefixed so they match at any depth:

| Before | After |
|---|---|
| `__pycache__/` | `**/__pycache__/` |
| `*.pyc` | `**/*.pyc` |
| `*.pyo` | `**/*.pyo` |
| `.pytest_cache/` | `**/.pytest_cache/` |

Added a two-line comment above the block recording *why* the prefix is load-bearing
(patterns are context-root-anchored with no implicit `**`), so a future editor does not
"simplify" it back.

`*.pyo` and `.pytest_cache/` were fixed on QA's explicit recommendation ("have the same
anchoring issue and are worth the same treatment while in the file"). I left `.env`,
`.env.*`, `*.pem`, `app.db*`, `.cache/`, `.git/`, `.gitignore`, `.venv/`, `node_modules/`,
`.DS_Store`, the Streamlit secrets/token lines, and the non-runtime directory list exactly
as written — QA verified those are root-only in this repo and correct as-is, and widening
them was not the failure surface.

## Note for QA on AC4's literal wording

AC4 names the pattern as `__pycache__/`. The file now says `**/__pycache__/`. An exact-line
`grep -qxF '__pycache__/'` check will therefore not match, while the criterion's stated
outcome ("a build context carries none of them into the image") is now met and was not met
before. `**/__pycache__/` is a superset of `__pycache__/` — the root-level probe above
confirms it empirically — so nothing AC4 asked for was dropped. The literal-string form was
what caused the miss.
