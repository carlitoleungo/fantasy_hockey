Two divergences from the Engineer's method, chosen for independence:

1. **I never mutated the repo's `.dockerignore` to run the negative control.** The Engineer
   swapped the file and restored it. I used BuildKit's per-Dockerfile
   `<dockerfile>.dockerignore` sidecar instead, so the repo file's hash is provably untouched
   across the whole session. This also removes the "did the restore work?" question entirely.
2. **I added a discriminator so the control could not be misread.** A sidecar that was silently
   ignored would fall back to the repo `.dockerignore` and also produce "probes absent", so
   absence alone would be ambiguous. I asserted that under the sidecar the *pre-change*
   semantics were genuinely in force: probes present **while** root `.env`, `.env.example`,
   `.git`, `tests/`, `docs/`, `.venv/` were all still excluded and `pyc=0`. That combination is
   only producible by the pre-change pattern list, not by "no ignore file" and not by the
   committed list.
